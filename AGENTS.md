# Repository Instructions

- Read `docs/PRODUCT_REQUIREMENTS.md` before making product changes.
- Work only on the milestone explicitly requested, and stop when it is complete.
- Do not add paid services, deferred features, or other out-of-scope work.
- Use React, Vite, TypeScript, Tailwind CSS, Supabase Free, and Netlify Free.
- Enforce permissions with Supabase Row Level Security and secure database
  functions, not only interface restrictions.
- Never commit passwords, `.env` files, access tokens, private keys, or the
  Supabase service-role key.
- Never use real employee information in tests, seed data, screenshots, or
  public preview deployments.
- Use `Australia/Melbourne` for roster date and time display.
- Preserve historical assignments rather than silently deleting them.
- After implementation milestones, run linting, type checking, tests, and the
  production build. Never claim a command passed unless it ran successfully.
- Report files changed, commands run, results, assumptions, and unresolved
  issues. Include PowerShell commands where they differ from Unix commands.
- Prefer small, maintainable solutions for an internal application of about
  ten users.
